# 读 BP 工作流 · Read-BP

一套面向**投资人**的商业计划书（BP）阅读工作流，跑在 Claude Code 里。覆盖从初读到长期跟踪的全流程：

```
① BP 阅读  →  ② 问题罗列  →  ③ 纪要整理  →  ④ 持续对话
```

## 怎么用

在 Claude Code 中，把要看的 BP（PDF）放进项目里，然后调用工作流：

```
/read-bp
```

或者直接对 Claude 说，例如：
- 「帮我读一下 `deals/某公司/source/bp.pdf` 这份商业计划书」（→ 阶段①）
- 「见创始人前，列一份要问的问题」（→ 阶段②）
- 「我把和创始人聊的要点发你，整理成纪要」（→ 阶段③）
- 「这个项目现在什么情况？对比一下 A 和 B」（→ 阶段④）

每个阶段都可以单独调用，Claude 会判断你处在哪一步。

## 四个阶段

| 阶段 | 做什么 | 产物 |
|------|--------|------|
| ① BP 阅读 | 读 PDF，输出结构化分析（团队/市场/产品/模式/数据/风险）+ 明确结论 | `01-分析.md` |
| ② 问题罗列 | 生成带优先级（P0/P1/P2）、可证伪的尽调问题清单 | `02-问题清单.md` |
| ③ 纪要整理 | 把与创始人的沟通整理成纪要，回填问题清单，更新结论 | `03-纪要-<日期>.md` |
| ④ 持续对话 | 长期跟踪项目，交叉验证新数据，随时追问/对比 | `04-跟踪.md` |

## 目录结构

```
.claude/skills/read-bp/
  SKILL.md                      # 工作流主逻辑
  references/
    analysis-template.md        # ① 分析框架
    questions-framework.md      # ② 问题框架（八大维度）
    minutes-template.md         # ③ 纪要模板
    tracking-template.md        # ④ 跟踪模板
deals/
  <公司简称>/                    # 每个项目一个文件夹
    source/                     # 原始 BP（PDF）
    01-分析.md
    02-问题清单.md
    03-纪要-<日期>.md
    04-跟踪.md
```

## 设计原则

- **站在出资方立场**：发现亮点，更要识别红旗和待验证假设，不替创始人美化。
- **区分声称与已验证**：BP 里的数字标注口径，存疑的流入问题清单。
- **每步落盘成文件**：所有分析沉淀在 `deals/` 下，支持长期复用和持续对话。
